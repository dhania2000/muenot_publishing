# P1-T06 Layout and rendition capability matrix

Version 1.0 · 29 October 2026 · depends on P1-T05 · documentation only.

The existing Layout Settings and Reader Preview pages are placeholders generated by `lib/conversion-modules.ts`. Extend them through `app/(workspace)/modules/publishing/conversion-name/[submodule]/[page]/page.tsx`, reusing the controls in `components/publishing/conversion/pdf/pdf-settings-components.tsx` and preview states in `pdf-preview-components.tsx`. No actual layout engine or reader exists yet.

## Proposed layout profiles

| ID | Layout and suitable source | Content and setting requirements | Reader limitation and fallback | Designed test book and acceptance |
| --- | --- | --- | --- | --- |
| LAY-01 | Reflowable; semantic DOCX/HTML/XML | Logical headings, paragraphs, tables, inline images, reader font/line-spacing overrides | Complex typography changes with viewport; provide semantic alternatives for wide content | L-RF: 3 chapters, long heading/table/notes; order and anchors survive font enlargement and narrow viewport |
| LAY-02 | Fixed pre-paginated; designed pages/IDML/rights-cleared PDF | Explicit viewport, page dimensions, logical text order and image descriptions; rendition layout/orientation choices | Zoom and accessibility behavior differ by reader; offer reflowable companion where appropriate | L-FX: image/text spread with live text; no clipping or missing labels at selected devices/zoom |
| LAY-03 | Spreads; illustrated books/comics | Left/right/center placement, intentional blank pages, page-progression and binding direction | Readers may display single pages; each page must remain understandable | L-SP: asymmetric two-page figure; correct single-page and spread sequences in named readers |
| LAY-04 | Mixed spine; narrative with fixed inserts | Explicit per-item layout decisions and transitions; preserve navigation and reading order | Mixed-layout support conditional; split into linked editions if incompatible | L-MX: reflow chapter → fixed insert → reflow chapter; transitions and bookmarks reviewed |
| LAY-05 | Multiple renditions; alternate complete editions | Separate package/rendition identity and selection policy; avoid duplicate-content navigation | [Multiple-Rendition Publications](https://www.w3.org/TR/epub-multi-rend/) is a Group Note; reader selection is not universal | L-MR: two renditions with shared assets; intentional selection/fallback tested, never random first package |
| LAY-06 | Continuous/“roll” presentation; long illustrated web-like content | Treat as a product profile; spine segmentation, orientation and accessible sequence documented | “Roll” is not a separate normative EPUB format; reader-controlled scrolling may differ | L-RO: long strip plus headings and alternate linear text; page/scroll alternatives verified |
| LAY-07 | RTL/vertical layouts; language-appropriate sources | Language and direction, progression, writing mode and licensed fonts; mixed-direction segments | Support depends on reader, script and font; retain a readable horizontal alternative if needed | L-DIR: Arabic/Hindi/English mixed passages and a vertical sample; no reordered punctuation or broken navigation |

[EPUB 3.3](https://www.w3.org/TR/epub-33/) provides the publication baseline; [Reading Systems 3.3](https://www.w3.org/TR/epub-rs-33/) guides reader test distinctions. The matrix proposes our product restrictions and fixtures; it does not assert every reader implements each setting.

## Transformation and accessibility rules

LAY-08: preserve source locator → content node → output resource links and a loss report. Image-only fixed pages cannot be presented as equivalent semantic text; attach reviewed text alternatives or hold accessibility claims. Resizing, column reduction and font substitution require reviewer-visible evidence when they change source intent.

LAY-09: orientation, viewport, spread and progression defaults belong to an immutable layout profile selected for a revision. Source page geometry may inform a suggestion, never silently override the selected target. Record a conflict if a client demands incompatible viewport/layout/reader properties.

LAY-10: all planned test books must cover TOC, landmarks, page navigation where applicable, text selection, keyboard operation, enlarged text and assistive reading order. Record reader/app version, OS, viewport and outcome. Browser preview alone is not device approval. No profile passes on screenshot similarity alone.

## Acceptance and gaps

Each requested layout has source suitability, fallback and fixture acceptance criteria. This completes the layout specification, not its fixture executions. Open dependencies: content model, layout builder, renderer isolation, licensed sample sources/fonts, actual target-reader list and manual accessibility checks. No runtime or PDF behavior changed. Change log: defined layout/rendition differences and constrained the ambiguous roll requirement.
