# Phase 3 Task 17 — evidence-aware Alt Text generation

Implemented on `feat/phase3-task08-math-ocr` on 2026-10-28. This branch is separate from `main`; no merge or deployment is performed by this task.

## Result
The existing single-image and batch generator can use bounded saved accessibility evidence when the tenant selects Advanced Description / Both and the relevant analysis types. Simple photographs and illustrations keep the standard description strategy. No new generator, paid analyzer call, queue, billing ledger or version store was introduced.

The server reads tenant/asset/exact-occurrence records, binds mathematical/diagram evidence to the current region analysis and image SHA-256, checks source frame safety and omits stale or foreign evidence. Latest raw OCR, corrections, verified transcription, formula syntax and tentative scientific structure remain separate. The JSON prompt budget is 32,000 characters including markup escaping, with at most 32 evidence entries; whole source/correction/validation groups are omitted rather than truncating Unicode or formulas. Unavailable relevant evidence produces an explicit fallback warning. A failed evidence read stops before a claim or credit reservation and defers the existing batch job.

Strategies cover text, math, charts, science, flowcharts, tables, maps and mixed panels. The prompt preserves source notation and requested Hindi/English prose, audience and reader level. It disallows exercise solving, speculative subject identities, diagnoses, proofs, pixel-derived numeric values, unsupported trends, invented cell values and verified reading-order claims. Chart values are recomposed from existing saved label decisions and admitted only as current confirmed printed labels. Domain inferences and historical document context embedded inside domain results are omitted. Existing explicitly supplied document occurrence context remains handled by the original document prompt path; ambiguous asset-to-occurrence resolution is now refused.

The same governed vision call generates Short Alt Text and the separate detailed description. Complex advanced results cannot automatically become decorative or omit their detailed description. The existing credit reservation now includes the actual evidence/context/classification prompt; the existing settlement and replay mechanism remains authoritative. All new generation entry-point results require review.

## Persistence and review
A nullable `generation_evidence_json` column extends `alt_text_versions`, with an explicit migration and duplicate-column-safe runtime schema upgrade. It records source hash, occurrence, analysis, source IDs/versions/states, strategy, language, provider, time, warnings, treatment and null guideline version. Model remains in the existing model column. No guideline is invented.

Regeneration of an approved asset creates a `generated_candidate` history row without replacing approved content, approval/reviewer fields or its active version. The transaction verifies the processing attempt under a row lock. Candidate sequence numbers remain separate from the active version; later edits/generations allocate beyond all existing history versions. Failed attempts restore the approved status. Request replay returns the exact saved candidate rather than a later/current text.

The existing Generate result tabs and History drawer show an expandable evidence summary with raw/corrected/transcription-reviewed/candidate states. A preserved-approval banner offers an explicit “Save candidate for review” action through the existing optimistic manual-edit endpoint. This action preserves current draft edits and creates an unapproved review version. Export continues to use current saved content until that explicit save. Candidate History text uses its recorded output language.

## Limits
No live MySQL connection, authenticated tenant environment, paid-provider fixture run or Hostinger deployment was available. SQL migrations and real database concurrency still need deployment-environment verification. Prompt rules and deterministic source filtering reduce unsupported claims but do not establish model accuracy, factual/scientific correctness or WCAG conformance. Recognition quality limits from earlier tasks remain, including weak raw mathematical OCR accuracy. Native chart data, image digitization, semantic equation verification, native table remediation, map geocoding and verified reading order remain unsupported. Advanced description is opt-in; default processing remains standard-only. Client guidelines and deeper document-context orchestration are addressed by subsequent tasks.
