# Task 15 — Chemistry, physics, biology and geometry evidence

Implemented on 2026-10-28. Subject-specific visual candidates and literal notation now extend the existing scientific inspector. All scientific claims remain unverified and require review. Source transcription verification is tracked separately and never upgrades a domain claim.

## Reuse and coverage
- Task 3 image/occurrence classification supplies manual/automated category hints, not subject ground truth. Existing scientific subject settings select chemistry, physics, biology and mathematics (geometry); they do not assert the detected subject.
- Task 14 completed structure supplies exact component, region, panel, label association and relationship references. Geometry regions are now eligible for scientific structure/domain inspection. Cross-panel claims and unsupported label/relationship/equation mappings are rejected; ambiguous label targets cannot be silently reduced to one component.
- Existing configured and authorized vision providers produce bounded subject-specific candidate kinds only. No provider-generated scientific names, values, diagnoses, SMILES, netlists, answers, proofs, approval or confidence fields are accepted.
- Chemistry candidates cover structure/atomic/bond drawings, reaction arrows and source-backed reactant/product/functional-group labels. Local checks preserve symbol spelling/case, printed atom-count tokens, Unicode subscripts and explicit charge glyphs. Plain digits before a charge sign remain ambiguous. Group multipliers are not expanded; unsupported strings retain their original text and warnings. Reaction arrows are transcribed without balancing or invented products.
- Physics candidates cover force/motion/free-body/ray/circuit/wire/source/meter/wave/vector/apparatus contexts. Arrow and wire claims require corresponding existing element kinds. Numeric/unit source labels reuse the bounded scalar parser; physical unit validity, measurements, component values and laws are not inferred. Wire crossings never create an electrically valid netlist or simulation.
- Biology candidates cover anatomy/cell/plant/organ-system/cycle/microscopy/comparative contexts using source labels and component references. No species, disease, tissue identity or function is established. Comparisons require multiple panels/groups.
- Geometry candidates cover point/line/angle/circle/triangle/polygon/marker/coordinate/dimension evidence. Literal markers and coordinates are preserved. Drawing appearance never establishes equal lengths, right angles, mathematical correctness or proofs.
- Tasks 8–10 math evidence is included only when asset, occurrence, source digest, region-analysis identity/version and referenced region match. Original and human-corrected LaTeX, review IDs/states and syntax status remain separate. Rejected equations cannot support a domain claim. No math recognition, formula solving or new MathML execution is triggered.
- Existing clean, currently accessible document-occurrence context is optional. Context must already be analyzed, match its exact document/occurrence and version, and remain within bounds. Current document ownership/scope is checked both when loading support and when exposing historical result context. Inaccessible historical context is redacted from the response without changing the saved record. No client terminology glossary/source is available in this service; guidelines remain optional and no terminology normalization is claimed.

Scientific accuracy stays false; confidence remains null. All unsupported capabilities (SMILES, balancing, netlist, simulation, diagnosis and geometry proof) are explicitly false.

Support counts/text and provider output are bounded, with a hard prompt limit before metering. Received results can finish after interruption without another provider call; a billed operation with no persisted receipt requires reconciliation.

A shared comparison issue was also corrected: MySQL JSON object-key order must not make unchanged snapshots appear stale. Server evidence checks now use structural equality across math, chart axes/data and advanced jobs. Object key order is ignored; actual values, source strings, types and array order still matter. Existing enqueue fingerprints and request identities are unchanged. Regression checks exercise recursively reordered persisted snapshots.
