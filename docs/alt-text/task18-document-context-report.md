# Phase 3 Task 18 — document context and multimodal evidence

Implemented on `feat/phase3-task08-math-ocr`, 2026-10-28. PDF/PPTX context uses the existing readers and occurrence records. Live DOCX context extraction remains unsupported because the repository has no DOCX image/text extractor; its existing logical heading/paragraph builder is retained and tested. No document parser, final generator, OCR engine, insertion/export mechanism, queue or credit ledger was replaced.

## Integration and authorization
Single-image generation now resolves context server-side, just like the document batch path, and refreshes document ownership and scan status before a claim or paid call. An explicit positive occurrence ID is accepted; ambiguous asset mappings fail rather than choosing the first occurrence. The exact tenant, asset and occurrence are checked. Explicit occurrence request IDs are bound into a bounded operation hash to prevent replay across occurrences. An occurrence image checksum must match the actual private image bytes before its context is used.

Context analysis stores a source binding in the existing context JSON: original document SHA-256, opaque file-revision fingerprint, source locator and image checksum. Generation and context reads compare it against current authorized file metadata and occurrence mappings. Legacy, mismatched, failed, stale or unbound context is withheld with review notices; reanalysis remains explicit. Stored page-OCR identity/run changes also invalidate dependent context. Scientific-domain context support uses the same current-source checks and respects document-context opt-out. Approved description content remains protected by Task 17's candidate mechanism.

## Packet and provenance
The existing vision input composes image bytes, classification, regions, OCR/raw corrections, math/syntax status and chart/scientific evidence with a separate typed occurrence document packet in the same governed call. A document packet contains location, source binding, context version, detected scripts, effective context policy, source snippets, stable occurrence-bound references, duplicate references and warnings. Native source language is not invented when the readers expose only scripts. OCR language modes remain independent of output language.

Packets are bounded to 20 snippets, 600 characters per snippet and 8,000 serialized characters with markup escaping. Text is Unicode/grapheme bounded and remains untrusted JSON. Source text cannot change tenant identity, permissions, tools, commands, billing or disclosure. Image observations take precedence over contradictory document material; document-only information must be attributed. Presenter-only notes are excluded from generation by default, with an explicit tenant preference; source Alt Text and all document context also have existing-workspace policy controls.

PDF caption/heading associations reuse the current structure/proximity rules. Low-confidence unrelated same-page prose is excluded. Equal-strength conflicting captions are retained as separate candidates (up to three alternatives), with review warnings. Exact NFC/whitespace-equivalent text is included once with duplicate references retained; case, subscripts and compatibility notation are not folded into false matches. PPTX titles, associated shape text and optional presenter notes retain their source roles. DOCX heading/anchor/nearby-paragraph mapping is exercised through the existing pure layout contract, not advertised as a live extractor.

Selectable PDF text is explicitly labelled as having unknown native-versus-existing-OCR-layer origin; the parser cannot reliably distinguish those cases. Newly recognized page OCR remains separate. Only saved lines with a matching document hash/page/run and a reliable mapped image placement are eligible: at most eight lines / 1,800 source characters, fully within that image's bounds. Whole-page text is no longer attached merely because a figure is on the page. Embedded-region OCR and reviewed math/text retain their distinct Task 17 references. Full-page correction text is not assigned to old line geometry without a verified mapping.

## Persistence and reviewer view
Existing context rows and version history are reused; no schema change is needed beyond Task 17's JSON audit column. Generation metadata links the exact context version, source binding, packet fingerprint, source references and effective policy. A bounded private context snapshot is saved in the generation audit, while asset-only history/replay responses strip its raw excerpts. Document text is shown only through the authorized document context inspector. The inspector now shows the original image, source kinds/references/methods, conflicting captions and a collapsible generation-packet view. History/Generate evidence summaries show document snapshot references without exposing confidential excerpts.

## Limits and Task 19 readiness
No authenticated tenant, real MySQL concurrency run, paid-provider evaluation or Hostinger deployment was available. Files without verifiable current checksums cannot supply trusted current context. Unknown geometry, unrelated page OCR and unsupported DOCX extraction remain unavailable rather than invented. Visual-versus-caption semantic contradictions still require model/human review; deterministic checks preserve source disagreements but do not prove scientific correctness. Context association tiers are heuristic and uncalibrated. The bounded evidence/policy/snapshot contracts are ready for Task 19 terminology rules; optional client guidelines remain absent until implemented.
